## 变更与合同

`responses_protocol_parser.go` 从既有观察器移入事件、完整 JSON、item 和 part 解析。结果只包含本帧已观察标记、音频模式标记、按协议顺序排列的输出种类/Token 标记及终态分类/原因，不保留正文、时钟、上下文或请求 owner。组件可独立单测；没有新增接口、依赖或 goroutine。

`responsesOutputTiming` 在原 mutex 内解析并应用事实，仍是取消采样、计时时点、终态冻结和尝试观测的生命周期 owner。SSE/WS 事件先采样取消再检查正文，完整 JSON 仍先验证合法性再进入锁；纯 JSON 解析函数只接收这个入口已验证的完整 JSON。首次终态仍只由 `responsesCompletionClassifier.freeze` 决定。公开 `UsageTiming`、DTO、数据库字段、重试及异步提交 owner 均保持。

下列既有差别由回归保护：

- 显式事件类型优先于正文 `type`；未知显式类型、非法 JSON 和 `[DONE]` 不能借正文补造输出或完成。
- 媒体和 Token 输出顺序保持；终态汇总中的完整文本/工具 item 不生成流式首 Token，而媒体/compaction 仍可建立首次输出。
- 音频输出在计算时点有效后才成为音频事实；transcript 和结束标记独立确认音频模式，不能猜成零音频。起点之前的输出仍被忽略。
- 完整 JSON 中 compaction 只采集压缩结果，保留原有首次完成优先于 envelope 状态的规则；本阶段不修正或扩展协议语义。
- 上游原因继续使用原始 error 对象的稳定码和合法整数 HTTP 状态；SSE/WS 的嵌套 error 与 JSON 的直接 error 选择保持。

用量选择/合并、`observeAcceptedUsage`、音频总量替换及无音频确认仍由原实现负责；本帧事实不选择计费来源，也不发起持久化。HTTP normal/passthrough、缓冲 SSE、pooled WS、透传 registry 和 WS→HTTP bridge 的接线均无修改。
