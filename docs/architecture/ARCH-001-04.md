## 权威 owner 与合同

`responsesUsageAccumulator` 只持有 UsageSource、AudioOutputTokens 和本尝试已见音频事实，不选择 usage 对象、不累计计费 Token，也不冻结完成状态。零值组件表示尚未接受任何用量事实，快照明确为 unknown/NULL；实际已接受事实始终由纯解析函数给出来源。

`parseResponsesAcceptedUsage` 只消费调用者实际接受的 raw 对象，将来源、是否替换音频拆分和合法整数拆分转为标量事实；结果不保留正文或 raw 引用。非对象 raw 仍在原入口拒绝。HTTP extractor 的顶层/嵌套/data 包装优先级、relay 的嵌套优先和全零终态拒绝替换仍由各自原 parser 决定，本阶段不统一这两种来源规则。

保留以下状态转换：

- 部分帧缺失或非法音频拆分时保留已接受的旧拆分。
- 原 parser 实际接受 JSON/终态总量后，音频拆分随同替换；缺失或非法拆分清空旧部分值。
- 历史正音频拆分、有效音频输出和 transcript/end 模式标记共同阻止猜零；明确报告的零拆分仍可信。
- 完成/取消已经冻结时，drain 的已接受用量仍可更新来源和拆分；接受用量本身不生成协议终态。

`responsesCanConfirmNoAudio` 是原无音频证据检查的纯函数抽取，保留显式音频字段、兼容包装字段、未知输出种类和非数组输出的拒绝规则。它只判断协议内容能否确认，状态组件再按历史音频事实决定是否补齐零。

事实解析与状态更新继续在原 observer mutex 内；无音频内容检查仍在原锁之前执行、状态确认在锁内。请求取消、AfterFunc、首次终态、尝试/turn/response ID 归属及 HTTP/SSE/WS 接线不变。组件快照用既有 Clone 复制可空拆分，原观察器与输出/分类器/观测元数据组合成同一 public DTO。
