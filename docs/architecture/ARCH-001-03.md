## 状态归属与行为

`responsesOutputTimingTracker` 持有原转发起点与四个输出字段：首次输出毫秒/种类、严格首 Token 毫秒、末次 Token 毫秒。它只消费第二阶段的输出事实和入口实际观察时点，不读取协议正文、不解析用量、不分类终态、不提交观测、不创建 goroutine。

首次媒体可以先于严格首 Token；媒体不推进 Token 时点，文本/推理/工具输出按原规则推进。毫秒换算与负值拒绝沿用原实现；不在本阶段增加排序、取最大值或改变精度。末次 Token 是最后观察到的有效 Token 帧时点，若不同帧时点倒序，也不改写成时间最大值。

组件返回输出时点是否被接受，原观察器据此保留有效音频输出事实；transcript/end 模式标记仍由纯解析结果直接报告。`audioSeen`、accepted usage、总量替换、音频未知/零值确认均在原 owner，保持起点前输出与音频模式标记的区别。

输出组件的更新和快照都在原 `responsesOutputTiming.mu` 内执行；取消采样、首次终态分类器、AfterFunc 生命周期、重试/turn 归属和 HTTP/SSE/WS 接线不变。输出快照通过既有 `UsageTiming.Clone` 复制可空字段，观察器将它与独立复制的 accepted usage/服务状态元数据及分类器快照合成原 public DTO。不会让异步消费者共享组件可变字段。

唯一需要调整的旧测试内部读取从 `o.timing` 改为输出组件快照，仍检查 metadata/空 delta 不产生输出；没有删除或减弱该行为断言。
