## 时间、锁影响与发布限制

生产只读目录统计的 usage_logs 估计 142,173 行、表及索引约 293,240,832 字节；ops_error_logs 估计 3,456 行、约 17,014,784 字节；groups 估计 4 行。统计为 reltuples 估计，不包含业务行。两个平台约束所在表统计均为 0 行。

PostgreSQL 18.6 合成库最终定向验证的完整升级耗时：空库 811.35 ms、带一万条用量的旧 KIN 库 128.03 ms、带一万条用量的已迁移个人库 117.95 ms。这包含全部账本校验；不是单份 SQL 的纯执行时间。锁阻塞测试约 5.02 秒后失败，符合 251 的 5 秒设置。三路径、恢复及旧镜像启动的定向执行最终约 10.49 秒；锁失败及未知 checksum 检查复用同 SQL/runner 的已通过证据。

251/252/253 使用 ALTER TABLE，需要 ACCESS EXCLUSIVE 锁；251 的常量默认值和可空列没有历史回填，合成库 filenode 验证无用量表重写。254 建新表/索引及 groups 触发器，亦需相关 DDL 锁；新 242 删除约束也需表锁。251/254 自带 5 秒 lock_timeout；252/253/242 不自带该设置，常规初始化受现有 10 分钟上下文约束，AUTO_SETUP 则使用现有设置的超时。不能将合成库耗时推算为生产锁等待上限。

实际部署前需在维护窗口暂停相关写入、排查长事务和锁阻塞，在隔离生产副本重新计时。当前生产已执行四份个人 SQL，目标升级仅补新 242；其他受支持旧库仍需四份 DDL。现有部署控制面的固定升级证明不包含本次新 KIN / 新 242，因此不能拿旧 251–254 追加证明自动部署本候选；部署证明和阶段发布由后续任务交付，本任务不改控制面。

## 失败处理与回滚

1. 发布前保存当时固定镜像、迁移账本、数据库与应用数据备份，核对实际源 SHA 和本清单；现有历史备份不能代表之后的新写入。
2. 每份普通 SQL 和其账本插入在同一事务中；整个多文件升级不是一个事务。失败后停止发布，保留已提交前缀、失败身份和错误，检查锁或 checksum 根因，不手工删列、删表、改账本或扩大白名单。
3. 只修复已确认的阻塞条件，使用相同文件名和原内容重新运行；runner 跳过已提交项。251 锁失败再执行的真实路径已测试。
4. 应用回退保留新增列、表、函数、触发器、账本和状态数据；固定旧镜像启动兼容已验证。实际流量切换仍需后续受审的部署证明，不能绕过现有部署工具拒绝。没有本任务 DOWN SQL，不恢复已经删除的平台 CHECK 冒充完整降级。
5. 需要数据库恢复时，只向隔离的新库执行 `pg_restore --exit-on-error` 并核对完整账本、schema、数据及读写；本轮真实 dump/restore 已验证。覆盖在线计费库需要另行授权维护窗口，明确备份后写入损失，保存失败现场，不能由自动应用回退代替。

撤销本任务源码提交仅用于未部署的集成候选；不能删除任何受支持环境已执行的 SQL 身份。没有修改生产、测试部署或其他任务候选。最终候选 SHA、独立复核、适用 CI 与任务状态以本任务 PR 和维护者任务台账为准。
