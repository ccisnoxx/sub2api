- 固定原候选 `036ade78ee5732d0dc860c3293aa70807ec1ddf1` 与 [dry-run 38196678157](https://github.com/ccisnoxx/sub2api/actions/runs/38196678157) 的同一 OCI index `sha256:1d90265792a83cb65b780b3d068e83d21fbc6d0d63ce771ecd5c998b890df807` 在 [原生复测 38207446049](https://github.com/ccisnoxx/sub2api/actions/runs/38207446049) 完成 10 次隔离启动、完整五轮及 4,000 个测量请求，零意外错误。JSON 吞吐比 0.994063 / p95 比 1.002203；SSE 吞吐比 1.014273 / p95 比 1.012872，原门禁通过，容器与网络无残留。没有采样到 kernel OOM；内存周期采样不是每个瞬时状态的证明。
- 旧失败环境为 aarch64 Colima，注册 `/usr/bin/qemu-x86_64` 7.0.0、页大小 4096。异常在发 SQL 前的 Ent 新谓词单回调 append，申请约 218.22 TiB；已检查路径无共享 Predicate/Selector 的证据。独立只读调查没有确认应用数据竞争 finding。
- 同 VM 的 64 KiB 匿名私有 mmap 探针：amd64 模拟中 MADV_DONTNEED 返回成功而 65,536 字节全部仍非零；原生 arm64 正确清零。Go 1.27.2 的 4 MiB 堆回收/新分配探针在相同模拟默认环境崩溃，原生 arm64 及仅对诊断探针设置 `GODEBUG=madvdontneed=0` 的同一 amd64 二进制完成八轮。实际应用未设置此绕过选项。
- Go 1.27.2 的 `runtime/mem_linux.go:42` 使用 MADV_DONTNEED，`runtime/mheap.go:1428` 对已回收页依赖内核清零。该环境已复现的错误返回破坏此保证，与新 Predicate 残留 slice 头及异常分配一致；这属于有机制和反例支持的 OOM 归因，未取得崩溃对象的逐字节堆转储，不能声称已回放原崩溃的每个指令。依据 [Go 官方最低要求](https://go.dev/wiki/MinimumRequirements)和 [Go #77572](https://github.com/golang/go/issues/77572)，旧 QEMU 用户模拟不作为本任务验收环境。必要修复仅在隔离验证入口，不加应用锁、不加内存、不改运行默认值或阈值。
- 首次原生入口在 Docker 28 旧存储下加载 OCI 失败，应用尚未启动；针对该明确环境原因在一次性 runner 启用 containerd 存储后通过。该失败保留，不计作性能失败或成功。
