### nanoid 依赖路径与调用方式

- 生产路径 `vue@3.5.43 → @vue/compiler-sfc@3.5.43 → postcss@8.5.29 → nanoid@3.3.20`；其他 Vue 消费方通过相同 compiler-sfc 路径引入。
- 锁文件还包含开发构建路径 `postcss@8.5.23 → nanoid@3.3.18`。
- 安装源码的两份 `postcss/lib/input.js` 均通过 `require('nanoid/non-secure')` 调用 `nanoid(6)`，用于无路径 CSS 输入的内部 ID；应用源码没有 nanoid 导入、customAlphabet 或 customRandom 调用。
- [GHSA-2v37-7h3g-55p8](https://github.com/advisories/GHSA-2v37-7h3g-55p8) 的 3.x 修复下限为 3.3.18；当前两份锁定版本均已修复。无需新增 override 或继续保留例外。

### XLSX 两个短期例外

真实维护 owner 为 CODEOWNERS 中的 `@ccisnoxx`；两个例外均提前至 **2026-11-09** 到期，只匹配以下精确范围：

| 包及版本 | 完整依赖路径 | advisory |
| --- | --- | --- |
| `xlsx@0.18.5` | `. > xlsx@0.18.5` | `GHSA-4r6h-8v6p-xvw6` |
| `xlsx@0.18.5` | `. > xlsx@0.18.5` | `GHSA-5pgg-2g8v-p4x9` |

唯一应用入口是 [UsageView.vue](../../frontend/src/views/admin/UsageView.vue) 的 `exportToExcel`：由管理员触发，从 `adminUsageAPI.list` 分页取回结构化字段，经 `aoa_to_sheet` / `sheet_add_aoa` 构造工作表，再调用 `book_new`、`book_append_sheet` 和 `write` 写出 Blob。输入是后台字段值，不能把这些值称为完全可信；当前安全依据是没有把任何文件、上传字节或字符串交给表格解析器。

SheetJS 的[原型污染公告](https://cdn.sheetjs.com/advisories/CVE-2023-30533)明确指出不读取任意文件的导出流程不受影响。[ReDoS 公告](https://cdn.sheetjs.com/advisories/CVE-2024-22363)要求升级至 0.20.2 或更新版本；本路径不进入文件解析代码，因此当前不可利用判断来自调用路径核查，而非公告对所有写出函数的通用保证。

npm 的 `xlsx` 没有可直接升级到的修复版；官方修复版通过 SheetJS CDN 分发。切换分发源或写出库需要另行验证构建与导出兼容性，因此本次保留并缩短已有例外，而不引入新的分发来源。owner 应在到期前完成替换；新增解析、导入位置、依赖路径、版本或 advisory 均需重新评估。

## 门禁与验证

- [审计校验器](../../tools/check_pnpm_audit_exceptions.py)强制 reason、mitigation、owner、evidence、expiry、精确版本及完整依赖路径；匹配包名 + GHSA + 严重等级 + 每条 finding 的版本/路径，不能按包名忽略未来漏洞。
- 所有过期例外均失败，即使对应漏洞已经不再出现在报告中；到期当天仍有效，次日失效。审计服务错误、未知报告、缺少高危明细均失败。
- `check:xlsx-write-only` 使用现有 ESLint/Vue/TypeScript 解析器检查全部前端源码，只允许上述页面中的静态 `await import('xlsx')` 和五个已核实写出调用。其他导入、解析 API、计算属性、解构、引用逃逸、非静态 import/require 和源码内禁用规则均不能绕过检查。
- Security Scan 的前端 job 执行该静态检查、两组门禁回归测试和生产审计例外校验；现有失败状态没有降级。

实际通过的定向验证：

```bash
cd frontend
corepack pnpm@9.15.9 install --frozen-lockfile
corepack pnpm@9.15.9 audit --prod --audit-level=high --json --registry=https://registry.npmjs.org > audit.json || true
corepack pnpm@9.15.9 run test:xlsx-write-only
corepack pnpm@9.15.9 run check:xlsx-write-only
corepack pnpm@9.15.9 exec vitest run src/views/admin/__tests__/UsageView.spec.ts
cd ..
python3 tools/test_check_pnpm_audit_exceptions.py
python3 tools/check_pnpm_audit_exceptions.py --audit frontend/audit.json --exceptions .github/audit-exceptions.yml
git -c core.whitespace=cr-at-eol diff --check
```

审计命令退出 1 是因为两个 high 项，随后精确例外校验通过。Python 门禁测试 12 项、XLSX 规则测试 27 项、既有 UsageView 测试 14 项通过；未运行无关后端测试、全量前端测试或发布/数据库门禁。Python 原脚本保持 CRLF，diff 检查明确允许已有 CR 行尾。

首次静态扫描受到其他源码内既有 ESLint 指令影响，报告四个未注册规则；检查器改为禁止内联配置后，通过整份源码扫描，并增加禁用安全规则的负向用例。既有 UsageView 测试仅提示 Browserslist 数据较旧，未更新无关依赖。
