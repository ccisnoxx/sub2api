## 哈希安装与失败传播

所有 Python release-tools 安装使用 `pip install --require-hashes --only-binary=:all:`。只允许官方 PyYAML CPython 3.12 wheel：Linux x86_64 CI、macOS arm64 和 macOS x86_64。缺失哈希、字节不符或不支持的平台直接失败；不回退到 sdist，不通过未固定的隔离构建依赖制作 wheel。新增平台必须在独立升级 PR 中核对官方文件哈希。

扫描仍执行符号可达性检查 `govulncheck -show version,verbose ./...`。版本来自精确 Go 模块及 Go 校验和数据库；实际二进制模块版本另用 `go version -m` 核对。保留发现可调用漏洞时的非零退出码，不改用 JSON 模式或吞掉失败。当前版本源码与官方文档确认 JSON 模式即便发现漏洞也返回 0，不能直接替代原门禁。

漏洞数据库保持在线更新，不冻结旧数据库。文本日志输出同次扫描的 Go、Scanner、DB URL 和 DB updated；构建元数据记录源码、Go/pnpm 锁文件和 requirements 摘要。因新漏洞公告、npm audit 服务内容变化或审计例外到期造成的结果变化仍可能发生，应结合对应日志审查，不能承诺相同源码扫描结果永远相同。

## 实际版本与构建元数据

`toolchain.py` 只采集已请求工具的实际版本，并与固定值核对；命令失败、工具缺失或版本不符直接失败，不写成功元数据。GoReleaser `2.18.3` 的真实 `--version` 输出使用 `GitVersion` 字段。

报告包含 source SHA、workflow SHA、run ID、平台、`configured` 固定策略、`actual` 实际工具版本及六个白名单输入的 SHA-256。`configured` 中的镜像摘要表示配置输入，不能冒充运行时检验；BuildKit 实际 daemon 版本另由 `buildx inspect --bootstrap` 输出。报告不导出环境变量、业务配置、代码内容或完整扫描日志。

- 前端：`toolchain-frontend`，实际 Python、Node、pnpm。
- 每个二进制平台：`toolchain-binary-<goos>-<goarch>`，实际 Python、PyYAML、Go、GoReleaser。
- 镜像/发布准备：`toolchain-publication`，实际 Python、PyYAML、Go、GoReleaser、Buildx；正式外部写入之前核对版本。dry-run 报告同时包含该 JSON。
- 安全扫描：`security-toolchain`，实际 Python、Go、govulncheck；失败时也保留已产生的安全元数据。

Release 的报告脚本和策略随 prepare 的可信工具 artifact 运输；安全扫描在 checkout personal/候选之前保存工作流 revision 的工具。应用旧 tag 无需包含新脚本，报告仍绑定实际被构建/扫描的源码 SHA，不把工具 checkout 当成应用来源。

## 月度工具升级任务

新增只读 `Toolchain version review` 工作流，每月 1 日 `04:23 UTC` 和人工 dispatch 执行。只有配置合入默认分支后 GitHub schedule 才生效；本候选不会声称月度调度已发生。job 固定 Python，只查询官方候选版本、记录当前策略并输出维护任务到 run summary，不安装候选、不改固定值、不推送、不自动合并。

维护 owner 为本 fork 维护者 `ccisnoxx`。每月 review run 完成后：

1. 对照当前版本与官方稳定发布，人工检查 Node/Python 的支持状态、Go `go.mod` 精确版本、pnpm 9 与锁文件兼容性。
2. 若有应采用的更新，创建独立工具升级 PR，记录 release notes、来源、tag/module、wheel 哈希或镜像 index digest；GoReleaser 保持 v2，跨主版本必须明确另行授权。
3. 更新登记表和工作流精确输入；Docker/pnpm 变更同步更新包管理器声明和 builder pin，禁止仅改文档。
4. 运行策略/元数据正负向测试、哈希安装、actionlint、受影响 CI 与安全扫描；触及 Release 路径时运行最小适用 dry-run。
5. 取得精确候选的独立控制面复核，由维护者人工合并；没有升级则在 review run 记录维持版本的理由。不得借工具升级扩大审计例外或关闭失败检查。

## 风险、数据库影响与回滚

- 固定版本和摘要降低构建时工具漂移；Linux/macOS runner image、Docker daemon、Alpine/运行镜像及 apk 软件仓库仍是平台/运行依赖。本任务不声称逐字节可复现镜像，不引入 CI-003 的 SBOM/attestation，也不冻结漏洞数据库。
- govulncheck v1.9.0 需要 Go ≥ 1.26.0；当前应用 Go 1.27.2 满足。若以后扫描较旧源码，必须采用审查过的兼容策略，不能自动下载另一个 Go 工具链。
- 月度 review 以默认分支配置为准；尚未合并时不调度。控制增量尚未同步到 personal，必须按其来源、祖先及 Personal CI 门禁另行验证，不能合并 main 的旧应用树。
- 本任务没有修改恢复工具、SQL、迁移、schema 或业务数据；没有重做数据库恢复演练，不把工具验证当成数据库恢复证明。
- Database impact: none。
- Rollback: 未合并时关闭本任务 PR；已合并时普通 revert 本任务独立提交，保留 CI-001 的 Action SHA，禁止 reset/强推。撤销报告脚本与对应 workflow 消费者必须一起完成；回退会恢复工具浮动风险，应优先以独立 PR 固定到上一个已验证版本。无需数据库回退，不执行发布或部署。
