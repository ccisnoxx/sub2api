## 逐 job 权限与凭据

全部九份 workflow 顶层仅 `contents: read`。显式列出权限后，未列出的权限为 none，依据 [GitHub permissions 文档](https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax#permissions)。常规 CI、Security Scan、部署工具测试、月度工具检查及 Personal CI 测试均只读；全部额外授权如下：

| workflow / job | 额外权限 | 实际用途 |
|---|---|---|
| Release / prepare | actions、packages: read | 查询同 SHA 的 Personal CI、personal-ready 与现有 GHCR 版本；保存可信 main guard |
| Release / release | contents、packages: write；actions: read | 发布 GitHub Release 附件和 GHCR 索引/latest；写入前重复核对固定 CI、tag、源码与 digest |
| Personal release / prepare | contents、actions: write；packages: read | 创建绑定当前 personal SHA 的标签、显式 dispatch Release，查询成功门禁和版本占用 |
| Sync KlN into personal / sync | contents、pull-requests、actions: write | 普通 Git push 候选、创建/更新草稿 PR、dispatch Personal CI；这是维护写入，不授予测试 job 发布权限 |
| Personal CI / binding、personal-ready | pull-requests: read | 检查 PR head/base 与最新 personal；测试和本地复用 workflow 不继承此额外权限 |

Release publisher 同时承载正式发布和 dry-run，其 job 权限为正式发布所需集合；dry-run 继续由步骤条件及已有负向合同禁止 registry/Release 写入，不能声称其 runner 没有写 token。没有增加长期 secrets 或扩大权限。

上游 CLA 两个 job 的 `Wei-Shaw/sub2api` 条件在本 fork 始终 false，取消其顶层 actions/contents/pull-requests/statuses 写权限，保留归属和跳过条件。CLA 不 checkout、不运行 PR 脚本，仅引用固定 Action；将来启用本 fork CLA 须独立审查。删除旧 `sync-version-file`：prepare 只允许本 fork，而该 job 排除本 fork，所以不能执行，取消其无用途的写权限和凭据保存。

全部 checkout 显式 `persist-credentials: false`，唯一例外是 main 调度的同步 job，显式 true 并注释 `sync.py` 普通 Git push 的用途。Release 标签由 API 创建，Release/镜像通过显式步骤 token 发布，构建 job 无需持久 Git 凭据；依据固定 [checkout 输入](https://github.com/actions/checkout/blob/d23441a48e516b6c34aea4fa41551a30e30af803/action.yml)。

## PR 与生产 secrets

普通 PR（含 fork）的 CI、Security Scan、Personal CI 不引用生产 secrets，不传 `secrets: inherit`。内置 GITHUB_TOKEN 只按显式只读权限使用。pull_request_target 仅为在本 fork 跳过的 CLA，默认只读，不 checkout 或执行 PR 代码。生产 DockerHub/Telegram secrets 只被无 PR 触发器的 Release publisher 引用，正式路径保留可信 main guard。

Personal release 仅允许维护者在本 fork 的 main 手动触发并启用发布开关；Release 仅保留 workflow_dispatch，标签推送不触发发布。发布只接受同 SHA 的成功手动 Full，不再查询分支保护/check-runs，相应 checks: read 权限已移除；同步写 job 只允许 main schedule/手动调度。没有修改仓库 Actions 设置、生产 secrets 或 environment。只读 API 确认默认 token 为 read、fork PR 审批为 first_time_contributors、自动合并关闭。公共仓库不支持 private-repo fork settings API（HTTP 422），该接口不能证明额外设置；隔离依靠显式权限和 secrets 规则。未创建真实外部 fork PR或读取生产 secret 值。

## 上传与保留

全部 16 处 upload-artifact 关闭 hidden files，仅允许既有可信工具/构建输出路径，并排除 `.env`、`.env.*`、`*.env`、SQL/数据库转储、backup/bak/db/sqlite、`*.log` 和 `.git`。禁止添加根目录/任意目录、环境配置、数据库备份或完整运行日志上传。runner.temp 正向路径的排除必须使用相同绝对根，workspace 内路径才使用相对排除。目录产物由既有可信生产者生成；文件名排除不能检测任意伪装文件或归档内部内容，不将其当作通用 DLP。

| 类型 | 保留期 | 用途 |
|---|---|---|
| release/sync/guard 工具、VERSION、前端 dist、目标二进制 | 1 天 | 同次 run 运输；到期后重跑完整流程，不绕过缺失 guard/归档 |
| dry-run OCI tar | 1 天（原 3 天） | 大体积镜像与原生证明，及时消费验证 |
| dry-run checksums/白名单 metadata | 3 天 | 失败诊断和人工核对，不上传原始日志 |
| SBOM、provenance、verification、publication 和发布工具版本 | 90 天 | 源码/工具/digest 审计，仅有白名单字段和哈希；正式 Release 附件长期分发 |
| 安全工具版本摘要 | 30 天（原 90 天） | 周扫描追溯，不上传完整扫描日志 |
| 月度工具复查摘要 | 35 天（原 90 天） | 相邻月度复查证据；升级经独立 PR |

路径白名单、保留期与排除规则由 `test_workflow_security.py` 在现有 release-helpers job 校验；排除路径不改变下载目录和可信工具结构，依据固定 [upload-artifact 输入与路径规则](https://github.com/actions/upload-artifact/blob/cf430e030ddbb5b0abf93d22962f4752f3646cd9/README.md)。保留期是自动到期规则，不保证永久保存或防删除；未等待实际到期删除。

## 并发与验证

Release 正式发布和 dry-run 使用不同并发组，均 `cancel-in-progress: false`。正式发布仍跨版本串行，防止并发更新 latest；dry-run 无法替换其中排队的正式发布。Personal release 保留独立串行组和 false，CI/安全扫描可取消组与发布组不重叠，复用检查仍按 source_sha/run_id 隔离。

GitHub 默认每组只有一个 pending run，新的正式发布仍可能替换旧 pending 发布；不承诺所有过期 personal SHA 发布。运行中的正式发布不被并发配置主动取消。未执行真实云端并发发布；规则见 [官方并发文档](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/control-workflow-concurrency)。

新增九项配置合同测试（首轮八项，加一项临时目录绝对排除回归），先在原工作流产生六个预期策略失败，再验证修正。负向覆盖测试写权限、默认/持久 Git 凭据、PR 生产 secrets（含全局 env、索引语法、完整上下文）、CLA PR 执行、敏感上传路径/过长保留期/hidden files、共享或可取消发布并发、缺失 fork gate 与新增 PR 发布触发。继续运行发布 guard/SBOM/工具固定测试和工作流语法检查；固定候选云端 CI、Release dry-run 与独立复核证据登记在 PR 和任务台账。首轮独立复核发现相对排除无法覆盖 runner.temp，按固定 Action 实际使用的 @actions/glob 0.6.1 复现三个工具目录日志/转储未被排除，再改为绝对根；七类目录真实 glob 正负向夹具确认必需文件保留、敏感文件排除。仅在隔离验证目录安装该精确库用于实验，不增加项目依赖；CI 策略测试拒绝相对根回退。
