## 绑定合同

- Personal release 准备器从 main 保存脚本后再检出 personal。正式 Release 的 guard、sibling sync 模块及所有构建/发布控制 helper 从同一次 main checkout 保存，记录完整 control SHA，再通过同次 artifact 运输；仅 dry-run 使用候选工作流 revision 的工具。所有授权及镜像 revision 查询从保存的 guard 执行；应用 checkout 及自带 release_matrix、supply_chain、release-images、personal_release、sync 脚本均不参与正式控制执行，不将整个 main 应用树合入 personal。
- Release job 在应用 checkout 后、artifact 下载前清理六个已知生成入口（release-input、release-evidence、.release-context、publication.json、publication-toolchain.json、dist），移除应用提交的 symlink，再由可信流程创建输出，防止上下文/材料写入覆盖 main guard。
- `personal_release.py` 核对 run 所属仓库及 head repository、workflow ID/path、personal 分支、完整源码 SHA、成功完成状态、可信触发事件、标题和实际必要检查所属 suite。旧 SHA 的成功 CI 不可用于当前 SHA；不设任意时间过期规则。
- 创建新 tag 前重新读取同一 CI；dispatch 前与 authorize 的远端 publication 查询后重新核对源码、CI 和 tag。错误/移动 tag、来源版本不符、镜像 revision/version/source/platform 不符均失败关闭。
- 全部发布步骤沿用 prepare 输出的同一 CI run ID，不因手动输入留空或同 SHA 新 run 成功而切换身份。OCI 推送前、latest 更新前及 GitHub Release 写入前再次执行 guard；latest 还须保持已验证 digest。最终 Release 要求当前 guard、publication 记录和 published image 构建摘要的 digest 非空且完全一致；版本入口被替换或删除时停止。失败后的正确镜像复用和不可覆盖版本合同保持。
- dry-run 仍核对请求 SHA 与实际 checkout，生成构建、SBOM 和 OCI 验证材料；跳过发布 guard、registry 登录和外部写入。既有 job 的权限声明没有在本任务调整，权限整理属于 CI-005。

## 风险、数据库影响和回滚

生产 guard 来自每次 prepare 实际检出的 main SHA，随后固定为同次 artifact。必须先依序合并控制面依赖与本任务，再按仓库规则同步必要控制文件到 personal，候选 PR 本身不会更新生产 guard。此合同依赖可信 Actions 工作流、main 审查和 artifact 运输；不能阻止维护者绕过整个受审工作流，也不提供跨 GitHub/GHCR 的原子事务。最后一次检查与外部写入之间仍有并发窗口；部分写入后失败须保留原 tag/SHA/digest，按同一身份恢复。

数据库影响：none。没有 SQL、迁移、schema、数据库运行配置或恢复工具变更；不重复数据库恢复演练，不将既有恢复证据冒称为本次执行。

未合并时关闭本任务 PR。合并后通过普通 revert 撤销 CI-004 增量，包括 guard 的保存/运输/调用位置、写入前检查、相应测试和任务文档；须一起撤销生产者与消费者，保留 CI-001/002 pins 和 CI-003 证明合同。禁止 reset/强推、移动正式 tag 或覆盖镜像 digest；无需 SQL 回退。
