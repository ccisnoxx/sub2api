## Summary

- 聚合每分钟执行、业务事务预算 45 秒。每轮记录耗时、阶段、源扫描返回行数、已提交事实行数、进程累计失败数和连续失败数。跳过 advisory lock 不刷新成功或清零连续失败；正常停机取消不计失败。

- 首轮及随后每小时采集事实表 UTC 当日/前日逻辑行数、主表/索引/总大小、活/死元组估计、autovacuum、统计重置及长事务数。采样使用独立的只读事务，最多两秒，失败只报告监控异常，不改变已提交业务事务。首次部署不需要新 schema 或新的长期凭据。

## 指标与告警

结构化日志 logger 为 `service.service_status`，事件名固定：

| event | 主要字段 | 口径 |
|---|---|---|
| `service_status_aggregate` | `duration_ms`、`source_rows_loaded`、`scan_completed`、`facts_rows_committed`、`failures_total`、`consecutive_failures`、`stage`、`outcome` | 源扫描返回行数是加载到应用的行数，不是 PostgreSQL 执行计划实际访问的行/页数；扫描未完成时不得将零解读为没有源数据。事实行数包含十分钟重写，不能累计为每日新增事实。 |
| `service_status_cleanup` | `duration_ms`、`facts_deleted`、`incidents_deleted`、`scope_states_deleted`、`facts_delete_attempted`、`outcome` | 删除数仅在整个事务确认提交后计入；`commit_confirmed=false` 表示没有确认提交的删除数，COMMIT 错误时最终提交结果未知，不将其断言为回滚。SQL 清理耗时不包含后续聚合/提交。 |
| `service_status_capacity` | `today_rows`、`yesterday_rows`、`table_bytes`、`index_bytes`、`total_bytes`、`dead_tuples_estimate`、`last_autovacuum`、`autovacuum_count`、`stats_reset`、`long_transactions`、`activity_complete` | UTC 日行数是当前保留的逻辑事实数，不能用因重算产生的 `n_tup_ins` 替代。元组数是 [PostgreSQL 官方统计口径](https://www.postgresql.org/docs/18/monitoring-stats.html)中的估计值；没有统计时间保持 NULL。 |

内置触发线如下。监控系统可按非空 `alert_code` 收集 WARN/ERROR；本任务没有向外部系统发送通知或在生产安装告警路由。

| alert_code | 触发条件 |
|---|---|
| `aggregation_timeout` | 业务调用期限耗尽，立即 ERROR。 |
| `aggregation_consecutive_failures` | 同一进程连续至少三次聚合失败，ERROR；跳锁不重置，确认成功才重置。 |
| `aggregation_slow` | 成功聚合耗时至少 40 秒，WARN，留出一分钟周期余量。 |
| `capacity_growth` | 相邻成功采样总大小增加超过 64 MiB 且超过前次 25%，WARN。这是初始提示线，后续应按部署规模校准。 |
| `capacity_sample_failed` | 只读容量采样失败或超时，ERROR；本小时不会反复重试昂贵查询。 |

日常指标需要 INFO 日志。日志只包含固定阶段/码、计数和时间，不包含请求、模型、分组、账号、关联键或原始数据库错误；设置 `ops_system_log_skip` 防止监控日志再次写入同一个数据库。进程失败计数和增长基线在重启后重新开始，跨实例聚合由日志采集器负责。根据 [PostgreSQL 权限函数合同](https://www.postgresql.org/docs/18/functions-info.html#FUNCTIONS-INFO-ACCESS-TABLE)使用 `USAGE` 检查当前可用权限；权限不足时 `activity_complete=false`，长事务统计仅表示当前角色可见范围，不能解释为全库没有长事务；本任务不扩大数据库权限。

容量采样命令：

```bash
psql -X -v ON_ERROR_STOP=1 -f tools/service-status-capacity.sql
```

连接通过现有 `PGSERVICE` 或环境提供，勿把连接串写入命令、报告或 artifact。脚本明确 READ ONLY、5 秒语句预算、1 秒锁预算；超时保留失败，不删除数据或执行 VACUUM。需要完整跨角色活动统计时由管理员提供既有合适身份，不自动授权新角色。

## 真实容量依据

维护者授权后，通过原生 SSH 别名 `hostdzire` 查询实际部署的 `sub2api-kin-postgres`，仅在只读事务中运行上述 SQL。采样时刻为 **2026-10-11 09:11:59 PDT / 16:11:59 UTC**，PostgreSQL 18.6；服务状态启用，成功水位为 16:11:00 UTC，末次错误码为空，水位距采样约 59 秒。

| 指标 | 实测 |
|---|---:|
| 保留事实行数 | 916 |
| 2026-10-10 UTC 逻辑行数（部分日） | 149 |
| 2026-10-11 UTC 逻辑行数（部分日） | 767 |
| 主表大小 | 180,224 字节 |
| 索引大小 | 73,728 字节 |
| 总大小 | 253,952 字节 |
| 平均 tuple 大小 | 112.92 字节 |
| 每分钟已观察峰值范围数 | 3 |
| 死元组估计 | 59 |
| autovacuum 次数 | 65 |
| 最近 autovacuum | 2026-10-11 16:00:10 UTC |
| 过期事实 / 长事务 | 0 / 0 |

事实样本从 2026-10-10 12:15 到 2026-10-11 16:10 UTC，共约 27 小时 55 分钟。两天均非完整日，不能直接当作稳定日新增率。按照**已观察峰值三范围每分钟持续全天**估计，31 天为 `3 × 1440 × 31 = 133,920` 行；按当前总物理大小/逻辑行数估计约 **37.13 MB / 35.41 MiB**（包含当前空闲空间、索引及重算痕迹，不代表精确长期字节增长）。

隔离 PostgreSQL 以三个范围/分钟生成 133,890 条旧分钟事实，执行相同仓储聚合及首轮容量采样：最终修正候选总调用 **15 ms**，主表 15,704,064 字节、索引 10,510,336 字节，合计约 **25 MiB**。这支持当前规模继续保留 31 天；没有容量证据要求分区、降采样或调整保留期，因此不新增这些机制。真实部署相同源查询在只读 `EXPLAIN (ANALYZE, BUFFERS)` 中返回 14 行，执行 **2.045 ms**、243 个 shared hit blocks、0 read blocks；它只证明当时源读取成本，不冒充线上完整写事务耗时。

上述为初始评估，不能代表未来组/模型增加、流量峰值、索引膨胀或 31 天长期负载。上线后保留每小时采样和完整 UTC 日序列，关注基数、物理大小与死元组趋势；若规模改变，应重新评估。本任务没有在生产运行新聚合代码、修改设置、删除数据或部署应用。

## Risks

- 实际事实样本不到两天，31 天结论是有数据依据的初始估计；合成负载不能代替生产长期表现。新监控尚未生产部署，尚无线上新指标 p95/p99 或通知投递证明。
- 大规模部署两天精确计数可能超过两秒，届时采样明确失败而不是伪造零；应按实际趋势再决定采样策略。小时增长采样不是跨小时/跨重启的持久计数。
- 固定告警码提供应用告警信号；外部通知路由、watermark 停滞/source-error 运行手册仍属于 OBS-004，不在本任务安装或发送。
- 本补丁未改变 API/前端、SQL 迁移、聚合计费边界和网关转发；无需重新运行前端、整套部署、Release dry-run 或数据库恢复演练。

## Database impact

无 DDL、迁移身份、账本或保留期变更。仅在原聚合事务上读取 `RowsAffected`，事务外新增受时间限制的只读查询。原有 31 天 TTL 和三个 DELETE 的谓词不变。新应用使用既有 254 schema；旧应用回退继续使用相同 schema，历史事实、水位和事故保留。真实环境只做读取，没有备份恢复、权限变更或手工清理。
