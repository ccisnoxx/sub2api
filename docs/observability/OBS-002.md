# OBS-002：诊断与服务状态隐私边界

## Summary

本任务只增加诊断数据的展示保护、查询约束和审计，基准为 personal `fb3be6334d97cc1c5b3a1418ecfcf9f560530cfb`。前置 UPSTREAM-004 的路由诊断实现与该树一致，UPSTREAM-005 的验收提交 `39753447cb4287c1a0aeee68b79b589ff345498a` 是该基准的祖先；阶段原 PR 开放不代表这些实现未纳入已切换 personal。

服务状态 HTTP 使用明确的 v2 展示 DTO，有效样本门槛为 `max(5, minimum_samples)`。旧配置的 1–4 仍可读取、编辑或停用，但不能降低展示隐私门槛。低样本叶子及历史点整体隐藏，包含组名、组 ID、模型、计数、比例和证据时间。受影响平台的所有计数及比例返回 `null`，防止合计减去可见叶子重建隐藏样本；空叶子也适用。健康摘要不会用隐藏叶子的低阈值判定宣称全站正常。

证据时间和事件时间只显示 UTC 小时。事件只有在当前叶子足量、检测/异常/末次证据/恢复及每条更新的时间都落入足量历史桶时展示，否则隐藏整个事件及叶子的事件关联；由隐藏事件产生的 recovering 转为 unknown，并从获准展示的叶子重新计算平台及总览，不能显示为已恢复。展示事件数只统计获准展示的事件；近期事件可能要等待完整历史小时，低流量或长期等待证据的事件可能持续隐藏。底层事件推进、事实和健康判定 owner 没有改写。

原始事件读取保留当前已完成分钟及最多 200 条恢复事件。展示恢复候选在同一 repeatable-read 事务独立读取，检测与恢复都必须早于固定历史整点终点，同样最多 200 条；展示的开放事件复用原集合，再执行全部隐私证据门槛。当前小时隐藏事件的恢复不能通过占用候选上限挤掉既有可见历史。额外查询失败仍显式返回不可用，不回退到原始恢复集合。

## 查询与导出

- 服务状态只接受 `range=24h|7d|30d` 和单个具体 `platform`。历史终点固定为最近完整 UTC 小时，分别按 1 小时、6 小时、24 小时分桶；拒绝任意起止时间、组、模型、用户范围、重复参数及导出参数。
- `GET /api/v1/admin/ops/errors/:id/routing-diagnostics` 只返回验证过的 v1 选择事实或 `null`，只接受单记录、最近 30 天、不接受查询参数。响应不含内部账号、凭据域、API Key、用户身份、请求或故障正文。
- 原 Ops 单详情和关联批量详情不再输出顶层或 upstream events 中的 `routing_diagnostics`。历史可选 upstream_errors 非数组时只隐藏该字段、记录不含原串的固定异常信号，其余真实故障正文仍返回；裁剪副本不改写仓储对象。既有故障日志授权和故障正文合同保留；前端诊断面板改从独立接口获取事实，诊断 404/429/503 不清空原故障详情，并明确提示诊断读取失败。普通用户 DTO 继续不含内部诊断。
- 服务状态配置、快照及独立诊断共用 Redis 每用户每分钟 20 次额度。额度跨进程、接口、记录 ID、平台及 range 共用，不受管理员豁免或普通面板限流关闭影响。拒绝返回 429 与 `Retry-After`；Redis/限流 owner 不可用返回 503，不读取诊断仓储。只接受管理员 JWT，管理 API Key 和普通用户不能通过新诊断入口；三个旧详情保持原认证及可用性，不使用新诊断额度，且不返回结构化诊断。
- 不提供 CSV/XLSX、批量诊断或原始事实导出。管理员仍能保存已返回的 JSON，此内容与页面采用同一裁剪投影；无法阻止已授权管理员在浏览器复制获准显示的数据。

## 审计

复用既有管理面审计：配置读取、配置更新、快照读取、独立诊断读取分别使用固定动作名；带 `export`、`format` 或 `download` 的拒绝请求记录 `admin.diagnostics.export.denied` 及实际失败状态。更新只附配置版本、启用状态、阈值等白名单标量，快照只附固定 range 和隐私裁剪标记。配置 body、诊断 query 和未经校验的路径参数整体不入库，非法字段中携带的请求正文也不会进入审计。事件保留与队列持久化仍使用既有审计 owner，本任务没有新增日志存储或吞掉其失败信号。

## Risks

阈值保护降低低样本展示风险，不构成严格匿名保证。小部署中同一 group/model 的五次请求仍可能来自一个用户；已有 Ops/用量日志授权和外部背景知识仍可能建立关联。部署方可提高现有 minimum_samples，但应结合实际流量，接受更多 unknown 与隐藏数据。服务状态仍使用现有滚动五分钟窗口；足量窗口之间的差分可能暴露变化，本任务不宣称实现差分隐私或撤销既有日志权限。

完整历史的候选上限在样本投影之前执行，低样本历史候选仍可能占用名额；返回列表不能解释为全部获准事件，也不承诺平台或固定范围之间不可关联。这项有界历史限制不允许当前小时恢复挤占展示名额；没有扩大为无界读取或事件存储重构。

v2 平台隐私计数为 `null`，新前后端必须一起交付，旧已打开页面需刷新；三个旧 Ops 单详情不再携带诊断字段，依赖该字段的管理客户端须切到独立接口。Redis 不可用时诊断与其配置接口不可用，恢复 Redis 后重试；其他管理流程和核心网关不受新增限流影响。只读复核和 CI 不能替代生产运行、长期流量或旧前端混用验证。

## Database impact

无 DDL、迁移、账本、保留期、事实写入、配置持久化格式、计费或事件推进变化。展示读取仍为原 repeatable-read 事务，只调整历史查询边界。旧 minimum_samples 配置兼容；不删除事实、用户记录或 incident，不新增生产回填。

## Rollback

通过新的受保护 PR 撤销本任务应用与前端增量并一起交付原前后端；保留原 schema、ledger、事实、事件和配置。无需 SQL 回退、清库、重放迁移或强推。撤销会恢复旧诊断响应、宽松管理员读取和低样本精确信息，应作为明确的隐私回退处理。若只需停用服务状态，用最新 version 提交完整配置将 enabled 设为 false；这不改路由诊断授权，也不影响网关转发。Redis 不可用时先恢复限流依赖或走受控应用回退。
